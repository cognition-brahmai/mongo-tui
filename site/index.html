A calmer server workflow

Stop translating every question into shell syntax.

MongoTUI keeps the familiar MongoDB concepts visible: namespaces on the left, query controls above, results in the middle, and the full document beside them.

  1. 01

    Connect with intent

    Test the deployment first. Save a named endpoint without saving URI credentials. Stay in read-only mode when the job calls for it.

    mongotui --profile production
  2. 02

    Ask for exactly what you need

    Filter with JSON or Extended JSON, then refine the result with projection, sort, collation, skip, limit, and max execution time.

    { "status": "active" }
  3. 03

    Inspect without losing your place

    Move through result rows, keep the query visible, and open a scrollable BSON-aware JSON inspector when a document needs attention.

    Tab -> PgDn -> inspect

What is here today

The useful parts of a database GUI, translated for terminals.

The first release focuses on safe exploration. It avoids pretending a TUI should be a web dashboard, while still giving you the context a raw shell session leaves out.

MongoTUI makes exploration easier, not permissions looser. Saved profiles strip URI credentials, query pages stay bounded, and server-side MongoDB roles remain the actual security boundary.
